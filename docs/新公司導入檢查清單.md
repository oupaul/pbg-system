# 新公司導入檢查清單

本系統是同一份程式碼分別部署給不同客戶公司、各自獨立安裝（不是多租戶 SaaS）。`deploy.sh`／`setup.sh` 的互動精靈只會詢問網站名稱、port 等**部署層**設定，不會詢問任何**業務規則**——新公司裝好系統、改完預設密碼之後，還需要依這份清單到後台把業務相關的清單資料設定成符合自己公司的實際情況，否則會直接沿用原本開發這套系統的公司的假設值（或完全空白）。

## 1. 帳號安全

- [ ] 用 `admin` / `admin123` 登入後，**立即到「使用者管理」變更密碼**（系統目前不會強制要求，需自行執行）
- [ ] 視需要建立其他使用者帳號，並確認每個人被指派的角色正確（見第 4 項）

## 2. 公司基本資料（系統設定 → 公司基本資料）

- [ ] 填寫公司名稱、統一編號
- [ ] 確認營業稅率（預設 5%，沿用台灣營業稅率；若非台灣公司或稅率不同，務必調整——此設定會直接影響新增專案表單「未稅金額」的自動試算）

## 3. 業務規則清單（以下四項全新安裝後預設是空的，需要自行新增，否則對應功能無法選擇任何選項）

- [ ] **類型管理**（`/project-types`）：新增公司實際會用到的專案類型（例如：專案、維護、顧問服務⋯視公司業務性質而定）
- [ ] **獎金類型管理**（`/bonus-types`）：新增公司的獎金/佣金類型名稱
- [ ] **獎金級距設定**（`/bonus-tiers`）：針對上面每個專案類型，設定對應的獎金比例與成本扣除率（用於「新增獎金」表單的「套用獎金級距」自動試算功能；不設定的話該功能不會出現，仍可手動輸入獎金金額，不影響基本功能）
- [ ] **客戶等級管理**（`/customer-levels`）：新增公司慣用的客戶分級方式（不一定要是 A/B/C，可以是任何名稱，例如「重點客戶／一般客戶」）

> 以上四項如果是從舊版系統升級（而非全新安裝），系統會自動把既有資料中「已經在用」的值同步進來，不需要重新輸入；只有全新安裝才會是空白的。

## 4. 角色與權限（角色管理 `/roles`）

系統內建 4 個角色（系統管理員／專案管理員／業務員／老闆），但角色本身的權限旗標都可以自訂，也可以新增全新的自訂角色。導入新公司時建議確認：

- [ ] 各角色的「編輯資料」「刪除資料」「客戶/銷售機會編輯」權限是否符合公司實際的職務分工
- [ ] 「新客戶/廠商審核」權限（`can_approve_customer`）是否指派給正確的角色——預設只有系統管理員與專案管理員可以審核新客戶/廠商建立申請
- [ ] 「刪除審核」權限（`can_delete`）同上，只有具備此權限的角色才能核准他人的刪除申請
- [ ] 若公司組織架構跟內建 4 種角色不同（例如需要「主管」「财務」等），可以直接新增自訂角色並勾選對應權限

## 5. 通知設定（系統設定頁）

- [ ] 系統對外網址（`system_base_url`）：設定後，Email/LINE 通知裡的連結才會是可點擊的完整網址
- [ ] Email 通知：視需要設定 SMTP 帳密並啟用
- [ ] LINE 通知：視需要在 LINE Developers Console 建立 Messaging API Channel 並設定 Webhook
- [ ] 開票提醒、客戶追蹤提醒、閒置自動登出等各項數值型設定，依公司作業習慣調整預設值是否合適

## 6. 目前仍是系統寫死、尚未開放自訂的地方（如果公司的實際狀況跟這些預設值差異很大，需要修改程式碼）

以下欄位目前**還沒有**後台管理介面，若新公司的業務流程跟預設值不同，需要工程調整才能改變：

- 客戶往來狀態（往來中/暫停往來/已流失）、客戶身份類型（客戶/廠商/兩者皆是）
- 銷售機會狀態（洽談中/已成交/已流失）、活動類型（拜訪/電話/客訴/其他）
- 發票狀態（有效/作廢/整筆折讓）背後的核准/折讓邏輯
- 新客戶/廠商審核、刪除審核目前都只有單一層級（一人核准即定案），沒有多層簽核（例如先主管後總經理）的設計
- 介面語言固定繁體中文、金額顯示無多幣別支援、報表日期固定使用民國曆

如果導入的新公司需要這些項目支援自訂，請在導入前先確認清楚，評估是否需要額外開發。
